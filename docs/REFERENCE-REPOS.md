# Reference Source Repositories

Curated factual sources you can use as the `external/source-repo/` submodule
when applying this engine to a new topic. Every quiz question generated by
this system must cite an entry indexed from one of these repos — that's how
the no-hallucination rule is enforced (see `INSTRUCTIONS.md` § Factual
Grounding).

If your topic isn't listed yet, find a repo that fits the criteria below
and submit it via PR — see [How to suggest a reference repo](#how-to-suggest-a-reference-repo).

## How to suggest a reference repo

1. **Open a PR** adding a row under the relevant topic header (or a new
   topic header above "How to suggest"). Prefer the PR template
   `reference-repo.md` if the project ships one.
2. **Required fields** for the new row:
   - Repo URL (linked)
   - License (MIT, Apache-2.0, CC-BY-SA, etc.)
   - Content format (PDF / DOCX / Markdown / Flashcards / Code / mixed)
   - One-sentence note on coverage and quality
3. **Recommended**: link a draft `objectives.yaml` (gist or branch) showing
   how the repo's structure maps to domains/sections — saves the next
   porter from doing it from scratch.

### Bar for inclusion

A reference repo is accepted when it is:

- **Factually authoritative** — official publisher, recognized author,
  or otherwise verifiable against the exam/syllabus outline.
- **License-compatible** — the license permits the user to clone and
  reference the material privately. (We don't redistribute it; the user
  clones it themselves via `git submodule add`.)
- **Stable** — actively maintained, or stable enough that link rot is
  unlikely (e.g., publisher-owned org rather than a personal fork).
- **Coverage-complete** — covers the official exam/syllabus outline well
  enough that `objectives.yaml` can map to it without big gaps.

Repos that don't quite meet the bar can still be discussed in an issue
before opening a PR.
