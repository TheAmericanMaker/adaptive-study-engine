# Schema Reference

All tracking files in `tracking/` are validated against JSON Schemas in `schemas/`. This document is the human-readable reference.

`scripts/validate-tracking.py` enforces both schema validity and cross-file referential integrity. CI runs it on every push.

---

## `tracking/velocity-tracker.json`

Schema: `schemas/velocity-tracker.schema.json`

```json
{
  "examDate": "2026-05-25",
  "sessions": 12,
  "sessionHistory": [
    {
      "date": "2026-05-05",
      "domain": "D1",
      "score": 0.8,
      "questions": 5,
      "timeSpentMin": 25,
      "topicIds": ["1.1", "1.2"],
      "note": "diagnostic"
    }
  ],
  "accuracyTrend": [0.8, 0.6, 0.85],
  "projections": {
    "coverageAtExamDate": 0.92,
    "rolling7DayAccuracy": 0.78,
    "readiness": 0.72,
    "riskLevel": "MEDIUM",
    "recommendedDailyMinutes": 60,
    "recommendedQuestionsPerDay": 18
  }
}
```

- `sessionHistory` is append-only.
- `accuracyTrend` is the tail of session scores (last 30, kept by `log-session.py`).
- `projections` are recomputed by `log-session.py` after every session. All five projection fields are nullable until the first session is logged.

## `tracking/performance.json`

Schema: `schemas/performance.schema.json`

```json
{
  "topics": {
    "1.1": {
      "title": "First topic in domain D1",
      "domain": "D1",
      "questionsAnswered": 4,
      "correctAnswers": 3,
      "accuracy": 0.75,
      "level": 2,
      "confidence": "medium",
      "lastStudied": "2026-05-05",
      "streak": 1
    }
  }
}
```

- Keyed by topic ID matching `resources/objectives.yaml` subsection IDs (e.g. `"1.1"`, `"3.6"`).
- `level` ∈ {1, 2, 3}. Increments on ≥ 80% with no don't-know; decrements on < 60% or any don't-know.
- `confidence` ∈ {`unknown`, `low`, `medium`, `high`}.
- `streak` is signed: +N for N correct in a row, -N for N wrong in a row.

## `tracking/domain-coverage.json`

Schema: `schemas/domain-coverage.schema.json`

```json
{
  "version": "0.1.0",
  "domains": {
    "D1": {
      "name": "Domain 1 — display name",
      "weight": 0.12,
      "topicIds": ["1.1", "1.2", "..."],
      "topicsStudied": 5,
      "quizAccuracy": 0.78,
      "lastStudied": "2026-05-05"
    }
  }
}
```

- `weight` is the exam blueprint weight (must sum to 1.0 across domains).
- `topicIds` ⊆ keys of `performance.json` `topics`. Cross-checked by `validate-tracking.py`.
- `quizAccuracy` is null when `topicsStudied == 0`. **A non-null `quizAccuracy` paired with null `lastStudied` is rejected** — this is the "phantom data" bug class.

## `tracking/acronyms.json`

Schema: `schemas/acronyms.schema.json`

```json
{
  "acronyms": {
    "EXAMPLE": {
      "expansion": "Example acronym",
      "timesSeen": 3,
      "lastSeen": "2026-05-07",
      "confidence": "low",
      "sourceFile": "resources/source-content/section-03-some-topic.md",
      "sourceSection": "3.6"
    }
  }
}
```

- Populated automatically by `log-session.py` from each question's `acronyms` array.
- `confidence` drops to `low` whenever a question containing the acronym is wrong or marked don't-know; rises to `medium` on first correct answer; never auto-rises to `high` (manual review only).

## `tracking/question-history.jsonl`

Schema: `schemas/question-history.schema.json` (validates each line)

Append-only JSONL. One question per line:

```json
{"date":"2026-05-05","topicId":"1.1","question":"...","userAnswer":"Some option","correctAnswer":"Some option","correct":true,"dontKnow":false,"level":1,"sourceSection":"S1","sourceFile":"resources/source-content/section-01-...md"}
```

This file is the spaced-repetition substrate: `generate-schedule.py` and future scripts can sample weak/old questions to re-expose.

## `resources/indexes/source-section-map.json`

Schema: `schemas/source-section-map.schema.json`

Generated by `scripts/build-index.py` from `resources/objectives.yaml` + extracted PDF/DOCX content. Do NOT hand-edit; rerun the build script if the underlying source changes.

```json
{
  "version": "0.1.0",
  "sourceRepo": "<github-org>/<source-repo-name>",
  "domains": {
    "D1": {"name": "...", "weight": 0.12, "sections": ["S1", "S3"]}
  },
  "sections": {
    "S1": {
      "sourceSection": 1,
      "title": "First section in the source material",
      "domain": "D1",
      "contentFile": "resources/source-content/section-01-first-section.md",
      "originalFile": "external/source-repo/your-study-guide.pdf",
      "subsections": [{"id": "1.1", "title": "First topic"}]
    }
  }
}
```

## Cross-file invariants enforced by `validate-tracking.py`

1. Every topic ID in `domain-coverage.json:domains.*.topicIds` exists in `performance.json:topics`.
2. Every topic ID in `performance.json:topics` is referenced by exactly one domain in `domain-coverage.json`.
3. The `domain` field of each topic in `performance.json` matches the domain that lists it.
4. Every topic ID exists in `resources/objectives.yaml` (no orphaned tracking entries).
5. `quizAccuracy != null` requires `lastStudied != null` (for both topics and domains).
6. Each line of `question-history.jsonl` validates against `question-history.schema.json`.

Run `python3 scripts/validate-tracking.py` to check.
